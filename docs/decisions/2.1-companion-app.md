# Decision 2.1: Extension + local companion app

**Date:** 11/18/2026 · **Status:** decided

## Decision

Build the rest of the pipeline (steps 4–12) as a **local companion app** that
runs on the user's computer alongside the Chrome extension. The extension keeps
doing what it is good at: tapping YouTube's audio, playing the video, and
muting/mixing on time. The companion runs the heavy Python/PyTorch models.

Once the full pipeline works and sounds good, we may try moving pieces back
into the extension (ONNX/WebGPU ports). That is a later, optional step — quality
first, packaging second.

## Why

- WhisperX, pyannote, MDX-Net/Demucs and F5-TTS/XTTS are Python/PyTorch tools.
  Their best versions don't run in a browser, and the in-browser ports that
  exist are smaller, slower, or missing.
- On a Mac, PyTorch can use the GPU (Metal/MPS), and the models get the
  computer's full memory instead of a browser tab's share. Running them in
  Chrome is what caused the 14 GB memory problem earlier.
- It lets us try the real models first and measure quality, instead of
  guessing which port is good enough.

## Which step runs where

| Step | Runs in | Notes |
|---|---|---|
| 1 Lookahead audio tap (decoded YouTube audio, mapped to playback time) | Extension | Already built; this is the companion's audio input |
| 2 Audio in | Extension → companion | 16 kHz PCM sent over the link (2.2); `yt-dlp` optional (2.3) |
| 3 Delay buffer | Extension | Already built (lookahead + delay line) |
| 4 Source separation | Companion | MDX-Net / Demucs; stems sent back for the mixer |
| 5 WhisperX ASR + Silero VAD + alignment | Companion | WhisperX proper (answers 5.4) |
| 6 Keyword spotter | Companion | Small model, trained in step 6 |
| 7 Profanity decision | Extension | Word list stays in the extension's settings |
| 8 Diarization | Companion | pyannote |
| 9–10 Voice samples + clone | Companion | One small shared model, one profile per speaker |
| 11 Fit to gap | Companion | Replacement words arrive already timed |
| 12 Mixer | Extension | Web Audio: mute vocal stem, crossfade replacement |
| 13 Player | Extension | Already built |

## How they connect (details in 2.2)

- The companion listens only on `127.0.0.1` (never the network).
- The extension sends lookahead audio chunks with their media times; the
  companion sends back words with timings, speaker labels, and (later) stems
  and replacement audio for upcoming swears.
- A pairing token so only the Clean Ears extension can use it.
- **If the companion isn't running, the extension keeps working** with today's
  in-browser Whisper, and the label says so. Nobody is left unfiltered.

## Audio source

Start with the audio the extension already decodes from YouTube's buffer
(step 1). It is exactly what the viewer hears, already mapped to playback time,
and needs no second download.

`yt-dlp → ffmpeg` (2.3) stays on the list as an option, since it could process
a whole video before it plays. It is for personal use only and goes against
YouTube's terms of service, so it is off by default and comes after 2.2 works.

## Costs we accept

- Two things to install: the extension plus the companion (Python environment
  and model downloads, likely a few GB).
- Mac first. Windows/Linux later if needed.
- The companion must be started (later: launch at login).
